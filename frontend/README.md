# Capibara — простой аналитический дашборд

React + TypeScript + Vite. Светлый минималистичный интерфейс: текстовые вкладки разделов в шапке, одна белая рабочая область со скруглениями и таблицы без графиков: разделы по возможностям,
выбор бизнес-вопроса и одна таблица. SQL-модель и база не изменяются.

## Локальный запуск

Node.js 24, из `frontend/`:

```bash
npm ci
npm run dev
```

Открыть http://127.0.0.1:5174/ . Docker для этого не нужен.

```bash
npm run build
npm test
npm run preview
```

Production-превью: http://127.0.0.1:4174/ .

## Что доступно

- **Пульс продаж:** блок А — пять сохранённых SQL-ответов. Продажи по месяцам,
  топ продавцов, чек, повторные заказы площадки, категории.
- **Блок Б:** история цены, доставка по штатам, статусы, оплата/рассрочка,
  оценка и доставка. Вопрос 9 имеет два отдельных среза: штаты за 2018 год
  и способы оплаты за весь снимок.
- **Профиль продавца:** город/штат, выручка, заказы, единицы. Без подробного
  снимка доступны только продавцы из опубликованного топ-10.
- **Отмены:** пересчитываются при загрузке подробного снимка. Сумма известных
  позиций показывается с покрытием; без снимка выводится честное ожидание данных.
- **Доставка:** средняя стоимость на заказ и доля доставки из опубликованных
  итогов. Сроки доступны через отчёты 7 и 10 после подключения их результатов.
- **Возвращаются к продавцу:** пересчёт разных delivered-заказов у выбранного
  продавца внутри периода при наличии подробного снимка.
- **Рекомендации:** место для будущего расчёта; случайные товары не показываются.

Таблицы поддерживают сортировку по заголовкам, пагинацию и экспорт всего отчёта
в CSV. В категориях есть поиск, не меняющий доли. Полный ID доступен и копируется.

## Подключение данных

Сейчас `public/data/reports.json` содержит реальные сохранённые результаты из
`../model/results/`, а не числа, вписанные в компоненты. Время снимка показано в шапке.
Произвольные фильтры доступны только при подробных данных.

Перепаковать SQL-ответы без базы:

```bash
python3 scripts/export_dashboard.py --results-only
```

Скрипт подхватывает также `06_*.csv` … `10_*.csv`, когда они появятся в
`model/results/`. Для вопроса 9 допустимы два файла: заголовок `payment_type`
или `method` в имени означает срез способов оплаты; другой файл — штаты.
Альтернатива — выбрать вопрос в блоке Б и нажать «Загрузить результат CSV».
Файл читается локально, отдельно для выбранного вопроса/среза и не сохраняется
после перезагрузки. Он не объявляется автоматически проверенным результатом модели.

Для подробного снимка, когда PostgreSQL доступен:

```bash
# Подключение задаётся локальными PGHOST/PGPORT/PGUSER/PGDATABASE/PGPASSFILE.
python3 scripts/export_dashboard.py
```

Необязательно, если команда уже использует работающий контейнер:

```bash
python3 scripts/export_dashboard.py --container hack_postgres
```

Запрос выполняется в одной транзакции REPEATABLE READ READ ONLY. Скрипт не
запускает Docker, не пересобирает модель и не меняет данные. Большой
`public/data/dashboard.json` исключён из Git. После успешного экспорта обновляется
`public/data/index.json`. Ручная загрузка JSON из интерфейса убрана; снимок подключается автоматически через `data/index.json`.

Формат JSON версии 1:

- `meta`: schema_version, snapshot_id, exported_at, source_label,
  source_purchase_date_min/max, currency_code. Границы дат обязательны у подробного
  снимка и могут быть null у агрегатов. Экспортёр добавляет record_counts.
- `orders`: order_id, buyer_id, status, purchased_at — все статусы.
- `items`: order_item_id, order_id, seller_id, category_id, price_cents, freight_cents.
- `sellers`: seller_id, city, state.
- `categories`: category_id, category_code, category_name_en, category_label.

Ключи подробного снимка — канонические UUID, суммы — безопасные целые сотые.
Даты покупки без часового пояса. Проверяются ключи, связи, дубли, суммы и
полнота delivered-заказов. Ошибка не заменяется нулевыми результатами.

## Правила

Выручка — delivered без доставки; чек включает доставку и усредняется по заказам.
Повторность площадки использует все статусы. Повтор продавца — только delivered
и минимум два разных заказа внутри выбранного периода. Период по дате оформления,
конечная дата включена. Проценты и средние пересчитываются, не складываются.

Нулевой результат, неизвестная сумма и отсутствие расчёта показываются раздельно.
Вопросы 6–10 не вычисляются из пяти агрегатов: нужны реальные результаты запросов.

## Уточнения после проверки интерфейса

Сортировка изолирована по отчёту и схеме; числовые значения сортируются до
форматирования, NULL всегда в конце. CSV выгружает весь результат, полный ID
и исходную точность, включая дробные значения импортированного CSV.
Кнопка «Сбросить фильтры» также очищает выбранного продавца.
Месячные фильтры требуют обе границы; выбор вне периода подробного снимка
не превращается в фиктивные нулевые продажи.

Контракты дополнительных отчётов, ограничения проверки CSV и предложения
по недостающим данным: [DATA_CONTRACTS.md](DATA_CONTRACTS.md).
